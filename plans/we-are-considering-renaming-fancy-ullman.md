# Rename "Ralph" → "Rauf"

## Context

The tool/repo is named **Ralph**, which collides with the generic "ralph" technique (the autonomous coding loop pattern has many independent implementations). We want to disambiguate **this specific tool/repo** from the generic term by renaming it to **Rauf**.

This is a full structural rename, not just cosmetic re-branding. "ralph" is load-bearing in many places: the CLI binary, npm package scope (`@rauf/*`), the per-project `.ralph/` directory and `.ralph.json` marker, the `RALPH.md` artifact, the `RALPH_ROOT` env var, the `X-Ralph-Request` HTTP header, and the loop protocol signals (`RALPH_DONE` etc.). Because the tool installs scaffolding into **other** projects, renaming breaks already-instrumented repos — so this plan also delivers a `rauf migrate` command to convert them in place.

**Locked decisions** (from clarifying questions):
1. **Full structural rename** — binary, packages, `.ralph/`→`.rauf/`, `.ralph.json`→`.rauf.json`, `RALPH.md`→`RAUF.md`, `RALPH_ROOT`→`RAUF_ROOT`, `X-Ralph-Request`→`X-Rauf-Request`, `~/.ralph/`→`~/.rauf/`.
2. **Loop signals hard-switch** — `RALPH_*` → `RAUF_*`; the parser drops `RALPH_*` recognition.
3. **Back-compat = migrate + legacy fallback** — read-only commands (`status`, `backlog list`) tolerate a legacy `.ralph/` project and warn the user to migrate; **running the loop requires migration first** (an unmigrated `RALPH.md` instructs Claude to emit `RALPH_*` signals the new parser rejects).
4. **Scope = everything** — this repo, the agent-plugins ecosystem (`ralph-support`, `feature-forge`), and the GitHub repo + local working directory.

**Decisions surfaced while vetting a real instrumented project** (see next section — these were undecided in the prior draft and are now locked):
5. **Nested `specs/*/.ralph/` loop-state dirs ARE migrated — directory-rename only, contents untouched.** *(Revised — the original "detect-and-report, don't migrate" was wrong; see Gap 2.)* Production `status.ts` (`scanActiveRoots`) walks the whole project and treats **any** `.ralph/` containing a `state.json` as a first-class rauf loop-state dir (multi-backlog: a per-spec backlog root like `specs/auth/` keeps its state in `specs/auth/.ralph/`, with no per-spec marker by design). Leaving them as `.ralph/` would make the post-Phase-2 code — which scans for `.rauf/` — silently lose all per-spec status/history. So `migrate` renames every `.ralph/`-with-`state.json` (root + nested) to `.rauf/` as a bare `fs.renameSync` (no content rewrite — nested dirs have no `RALPH.md`; their log/item text stays historical). Only a `.ralph/` with **no `state.json` and no marker** is the genuine "report-and-leave" case.
6. **The "is a loop running?" safety gate keys off `.loop.lock` pid-liveness, NOT `state.json.status`.** A dead process can leave `state.json` stuck at `"running"`; refusing on that string alone would make many real projects (including the sample) un-migratable.
7. **The global `~/.ralph/` dir is migrated by an explicit `rauf migrate --global` step** (move dir + rewrite contents), not by the per-project command and not silently abandoned.
8. **Archived files keep `ralph` in their filenames** (`.rauf/archive/*-ralph.log`, `*-DONE`) — historical snapshots are preserved byte-for-byte, names included. Accepted inconsistency, called out so it isn't mistaken for a miss.

**Decisions surfaced in the second vetting pass** (re-verified independently against source + the live consumer + agent-plugins; previously missing entirely):
9. **Foreign tool-config files that reference `.ralph/` are detect-and-report, not auto-rewritten.** The live consumer's `biome.json` lists `.ralph` in its ignore array, and it also has `.graphifyignore`, `.claude/settings.local.json`, and feature-forge `specs/*/.pipeline-state.json` referencing `.ralph`. These are NOT tool-owned by ralph-manager, so the migrator must not silently edit them — but it must surface them in `foreignConfigRefs` so the renamed `.rauf/` dir doesn't drop out of lint/ignore/state configs unnoticed. (Rationale: same principle as CLAUDE.md out-of-block refs — the migrator never edits files it doesn't own, but it must never leave a *silent* dangling reference either.)
10. **`forge-5-ralph-loop` must be migration-aware, not just renamed.** It is the highest cross-tool coupling (39 refs): it invokes the CLI directly (`ralph loop run/status/backlog list`, reads `.ralph/state.json`, `.ralph/ralph.log`, the `.ralph.json` install check, the `RALPH.md` fallback). After the rename it invokes `rauf …` and writes `.rauf/` per-feature dirs — but it runs against arbitrary consumer projects that may not be migrated yet, so it must **detect a legacy `.ralph/` install and instruct the user to `rauf migrate` first** rather than failing opaquely. (See Phase 7.)
11. **Renaming the `ralph-support` plugin and forge skills is a breaking change for already-installed plugin users** — there is no auto-migration for installed plugins. Bump versions in `marketplace.json`, and document that consumers must reinstall `rauf-support` and re-reference the renamed `forge-5-rauf-loop` / `raufIterationMultiplier`.

**Decisions surfaced in the third (recommendations) pass:**
12. **Hard binary cut-over — no transitional shim.** The old `ralph` binary/symlink is deleted at Phase 5 (a stale old-protocol binary on PATH is the bigger risk than a brief gap). **Consequence: feature-forge is non-functional from Phase 5 until Phase 7 completes** (its `forge-5` calls the now-renamed `rauf` binary). Do NOT run the forge pipeline during that window; sequence Phases 5→7 in one sitting to keep it short.
13. **Each repo that gets destructive edits gets its own pushed pre-rename tag.** The rauf repo gets `pre-rauf-rename` (Phase 0); **agent-plugins gets its own `pre-rauf-rename` tag pushed before any Phase-7 edit**. Consumer repos rely on their own git tree + the migrator's `.bak` files as the rollback net.
14. **Renames use `git mv`** (not delete+create) for `.ralph/`→`.rauf/`, `RALPH.md`→`RAUF.md`, package dirs, and skill dirs, so `git blame`/`log --follow` survive the rename.
15. **Keep the name "Rauf."** Spelling-level disambiguation (distinct binary/dir/package/marker identifiers) is the goal; the phonetic overlap with the generic "ralph" technique is accepted.

Intended outcome: a clean `rauf`-branded tool with no `ralph` identifiers, a tested in-place migration path for existing projects, and updated external integrations — with build/tests green at every checkpoint.

## Vetting against a real instrumented project

Validated the migration design against `/home/gary/workspace/starter-kitchen-sink-bun`, a live consumer with ralph installed plus a feature-forge pipeline on top. The plan's core assumptions held, but two vetting passes surfaced **seven gaps** (the first five in the original pass; Gaps 6–7 in an independent re-verification that also re-confirmed every source-side claim, line number, and the consumer's exact artifact inventory against `packages/`, the live consumer, and the agent-plugins tree):

**What matched the plan (good):**
- Marker `.ralph.json` shape is exactly as modeled: `{ralph:true, version, variant, installedAt, installedBy:"ralph-manager@0.1.0", profile, artifactHashes:{"RALPH.md":<sha>}, options}`. Single artifact hash keyed `"RALPH.md"`. The hash-rename-and-recompute step is correct.
- `CLAUDE.md` carries the managed block wrapped **exactly** in `<!-- ralph:start -->` … `<!-- ralph:end -->`, and **all** `ralph` tokens in that file fall inside it. The scoped-block rewrite is the right tool for the canonical case.
- Source constants confirmed: `schemas.ts:119` `ralph: z.literal(true)`; `config.ts:12-15` `MARKER_FILENAME=".ralph.json"`, `TOOL_CONFIG_DIR=~/.ralph`, `RALPH_ROOT_ENV="RALPH_ROOT"`; `signal-parser.ts` `matchSignal` hard-codes `RALPH_DONE/BLOCKED/NEEDS_HUMAN/REVIEW`.
- `RALPH.md` exists **only** in the root `.ralph/`; nested loop dirs have no `RALPH.md` (per-iteration prompt is assembled by the runner). So content-rewrite scope = root only is correct.

**Gap 1 — A stale `.loop.lock` + `state.json.status:"running"` would block migration.**
The sample's root `state.json` reads `"status":"running"` (iteration 8/20) with a `.ralph/.loop.lock` holding `{pid:3165440, startedAt, processStartTime}` from days ago — a **dead** process that never finalized state. The prior Phase-4 gate ("confirm state.json not running") would refuse to migrate this and most real abandoned loops. **Crucially, core already ships a lock module** (`packages/core/src/lock.ts`, with `lock.test.ts` exercising a stale pid `999999999` and a `processStartTime` field) — the migrator must **reuse it** to test pid-liveness and treat a dead lock as safe (and clean it). The `.loop.lock` file itself was entirely absent from the prior plan's surface area and preserve/handle lists.

**Gap 2 — Nested `specs/*/.ralph/` directories are rauf loop-state, and MUST be migrated** *(corrected understanding — the prior draft mis-classified these as out-of-scope feature-forge orphans).*
The sample has **five** `.ralph` dirs: the root install + `specs/{isolate-domain,kitchen-sink-sample,sample-isolate,datagrid}/.ralph/`. Each nested one has `state.json`, `ralph.log`, `progress.md`, `DONE` (one has `notes/`), and **no marker** (the only `.ralph.json` is at repo root). The prior draft concluded "leave them alone," but that's wrong: **production `status.ts` `scanActiveRoots`/`walkForStateFiles` (lines 518-597) recursively walks the whole project** — skipping only `SCAN_SKIP_DIRS = node_modules/.git/dist/build/coverage`, **not `specs/`** — and treats every dir named `.ralph` that contains a `state.json` as an active loop root (`backlog-root.ts`: multi-backlog puts a per-spec backlog at `specs/X/` with state in `specs/X/.ralph/`; no per-spec marker exists by design). forge-5 doesn't create a special dir — it just invokes rauf's own loop runner, which writes the standard `.ralph/` state. **After Phase 2 the scanner looks for `.rauf` by name and silently drops every un-migrated `.ralph/` dir** — all per-spec status/history/resumable state disappears from the tool. Decision #5 (revised): migrate **renames every `.ralph/`-containing-`state.json` (root + nested) to `.rauf/`** — a bare directory `renameSync`, no content rewrite (nested dirs have no `RALPH.md`; their `ralph.log`/item text is historical and stays — the next run writes a fresh `rauf.log`, `state.json`/`backlog.json`/`DONE` filenames are unchanged). The marker is the wrong discriminator; **`state.json` presence** is the right one. A `.ralph/` with neither `state.json` nor marker is the only "report-and-leave" case.

**Gap 3 — The global `~/.ralph/` dir has no on-disk move step.**
`~/.ralph/` currently holds `server.json` (server registry: port/pid) and `server.log` — note **no `config.json` exists yet**, so the prior Phase-7 line "update `~/.rauf/config.json` rootDirectory" assumed a file that may be absent and, more importantly, assumed the dir had already moved. Flipping `TOOL_CONFIG_DIR` to `~/.rauf` in code does **not** move existing global state; the tool would silently start fresh under `~/.rauf/`, abandoning `~/.ralph/`. Decision #7 adds an explicit `rauf migrate --global` (or documented manual `mv` + content-rewrite). `server.json`/`server.log` are ephemeral so data-loss risk is low, but a live server's PID/port registry going stale mid-transition is worth handling deliberately.

**Gap 4 — `rewriteRalphStrings` must be case-aware.**
Tool-owned content mixes four casings of the token: `ralph` (`.ralph/`), `RALPH` (`RALPH.md`, `RALPH_DONE`), `Ralph` (`X-Ralph-Request`), `RalphError` (PascalCase, in docs). A naive case-insensitive replace would corrupt casing; a single bare `RALPH`→`RAUF` global pass would also need ordering care against `RALPH_ROOT`/`RALPH_DONE`. The helper must map per-case and longest-token-first. The prior plan said "longest-match first" but never addressed **case**. (See helper spec below.)

**Gap 5 — `forge.config.json`'s `ralphIterationMultiplier` is outside migrate's reach.**
The feature-forge config schema (`plugins/feature-forge/references/forge-config-schema.json:43-48`, type `number`, default `1.5`) defines `ralphIterationMultiplier`. The sample's `forge.config.json` doesn't set it (uses the default), but other consumers might. `rauf migrate` only touches `.ralph/` tool files, so a consumer that set this key gets a stale/ignored key after the plugin renames it to `raufIterationMultiplier`. This cross-tool coupling needs an explicit note + a grep sweep during the agent-plugins rename (it's a feature-forge concern, not rauf-manager's migrator). Note the key is also replicated in `scripts/forge-init.sh` and `references/shared-conventions.md`, so the agent-plugins rename touches more than the schema file.

**Gap 6 — Foreign tool-config files reference `.ralph/` (the migrator never sees them).** *Newly found in the second pass — the prior draft asserted the sample had no out-of-scope refs beyond CLAUDE.md/.gitignore; that was wrong.* The live consumer has **four** non-ralph config files that name `.ralph`:
- `biome.json:59` — `.ralph` in the formatter/linter `ignore` array. After the dir rename to `.rauf/`, biome would *start* processing the renamed dir (could reformat `RAUF.md`/JSON on next run). Low harm, real surprise.
- `.graphifyignore` — one `.ralph` line (graphify would re-index the renamed dir).
- `.claude/settings.local.json` — references `.ralph` (likely a permission/allow rule).
- `specs/{isolate-domain,kitchen-sink-sample}/.pipeline-state.json` — feature-forge per-feature pipeline state pointing at the per-feature `.ralph/` loop dir. After the feature-forge rename (forge-5 writes `.rauf/`), these states point at the old path.

Per decision #9 the migrator must **detect and report** these in `foreignConfigRefs` (path + line + matched text), not rewrite them. This generalizes: any consumer may have `.dockerignore`, `tsconfig` excludes, `vite`/`turbo` config, prettier/eslint ignores naming `.ralph/`. A simple repo-wide grep for `.ralph` (excluding `.ralph/`, `.rauf/`, the migrator's own backups, and `node_modules/.git`) produces the report set.

**Gap 7 — agent-plugins embeds two copies of `backlog-schema.json` carrying `garygentry/ralph` `$id` URLs + "Ralph Backlog" title.** `plugins/ralph-support/skills/create-ralph-backlog/references/backlog.schema.json` and `plugins/feature-forge/skills/forge-4-backlog/references/backlog-schema.json` both hard-code the GitHub raw URL and title. These are independent of the rauf repo's generated schema and must be updated in Phase 7 (the GitHub redirect keeps old `$id` URLs resolving during transition, so this is consistency not breakage). Likewise, **`scripts/generate-json-schemas.ts:64` hard-codes `schema["title"] = "Ralph Backlog"`** in the *generator source* — it must be edited there, then the generator re-run (the `$id` at line 63 is computed from the repo URL, so it follows the repo rename automatically once that var changes).

**Also noted (lower severity):** `.ralph/.verification/VERIFY-*.md` exists and should join the explicit preserve list (carried by the dir rename; contents reference `.ralph/` paths but are historical, not the migrator's job). Archive filenames embed `ralph` (`20260607-cli-framework-ralph.log`, `2026-03-ralph.log` — confirmed 7 such files) → decision #8. The sample's `.gitignore` has **zero** ralph lines, validating that the line-scoped gitignore pass must no-op-and-skip cleanly when there's nothing to rewrite — **but note this repo's OWN `.gitignore` has 18 ralph lines** (`.ralph/ralph.log`, `.ralph/state.json`, `.ralph/DONE`, `.ralph/backlog.json.bak`, `ralph-bin`, `~/.ralph/`, plus `test-sandbox/.ralph/*`), so the Phase-4 dogfood line-scoped pass will be the real exercise of that code path, not the consumer run. Consumer agent-memory (`.claude/agent-memory/**`) and `plans/`/`docs/` prose also mention `ralph` — out of scope (regenerated / human prose), but they land in `foreignConfigRefs`-adjacent reporting if the grep is broad; keep the report scoped to config/state files to avoid noise.

## Implementation

Reconciliation of decision #2 vs #3: read-only commands (`status`, `backlog list`, `projects`) must **detect** a legacy `.ralph/` marker (raw-JSON check for `ralph:true`, since the new Zod schema rejects it) and print a "migrate to continue" warning instead of "not installed." The loop runner refuses to run a legacy project and tells the user to run `rauf migrate`.

### Part A — `rauf migrate` (build this FIRST, it's additive)

New pure module `packages/core/src/migrate.ts` (zero cli/web imports, `Result<T,E>`, atomic writes, path-sandboxed), exported from `core/src/index.ts`; CLI wrapper in `packages/cli/src/migrate-commands.ts`.

```ts
type MigrateState = "not_installed" | "legacy_ralph" | "already_rauf" | "partial" | "marker_corrupt";
function detectMigrationState(projectPath: string): Result<MigrateState>;
function planMigration(projectPath: string): Result<MigrateReport>;          // pure, no writes (powers --dry-run)
function migrate(projectPath: string, opts?: MigrateOptions): Result<MigrateReport>;
function migrateGlobal(opts?: MigrateOptions): Result<MigrateReport>;          // ~/.ralph → ~/.rauf
```

`MigrateReport` carries, in addition to the step list: `loopDirsRenamed: string[]` (every `.ralph/`-with-`state.json` renamed to `.rauf/` — root + nested per-spec, decision #5 revised), `foreignDirsReported: string[]` (any `.ralph/` with neither `state.json` nor marker — report-and-leave), `staleLocks: {path, pid}[]` (cleaned dead locks across **all** loop dirs, not just root), `claudeMdOutOfBlockRefs: {line:number, text:string}[]`, `foreignConfigRefs: {path:string, line:number, text:string}[]` (Gap 6 — `.ralph` mentions in `biome.json`/`.graphifyignore`/`.claude/settings.local.json`/`.pipeline-state.json`/etc., detected not rewritten), and `backupsCreated: string[]` — all surfaced to the user.

**Loop-liveness safety gate (run before any mutation).** Reuse `packages/core/src/lock.ts`, and check **every** loop dir the migration will rename, not just root — enumerate all `.ralph/.loop.lock` files (root + each `specs/**/.ralph/` discovered by the same `state.json` walk `status.ts` uses). For each: if `pid` is **alive** (and `processStartTime` matches, per the existing stale-detection logic), **refuse** with "a loop is currently running in `<dir>` — stop it first." If a lock is **stale** (process dead), proceed and delete it as part of migration (record in `staleLocks`). **Do NOT gate on `state.json.status`** — it can be permanently stuck at `"running"` after an abandoned loop (confirmed in the sample). This gate lives in `migrate()` (git-agnostic, core-pure) so it protects every consumer, not just the dogfood run.

**Detection** reads markers as **raw JSON** (not `readMarkerFile` — the new schema rejects legacy) and checks `obj.rauf===true` vs `obj.ralph===true`, plus `.ralph/` vs `.rauf/` dir presence. Mixed states → `partial` (resumable). A marker file that exists but **fails to parse** (truncated/corrupt JSON) → `marker_corrupt` → refuse with a clear message (don't fall through to `not_installed`, which would mislead). A dir present with no marker at all → still `not_installed` for the *install* check, but the loop-dir walk may still rename a `.ralph/`-with-`state.json` under it (multi-backlog roots have no marker by design).

**Loop-dir discovery (decision #5 revised).** During `planMigration`, run the same walk `status.ts` uses (`scanActiveRoots` logic, `SCAN_SKIP_DIRS`-aware) to find **all** `.ralph/` dirs. Classify each: contains `state.json` → it's a rauf loop-state dir → **rename to `.rauf/`** (record in `loopDirsRenamed`); neither `state.json` nor marker → report-and-leave (record in `foreignDirsReported`). This converts the root install *and* every per-spec multi-backlog dir in one pass, so `status`/loop keep working post-migration. The rename is a bare `fs.renameSync` per dir (children carried untouched); only the **root** dir additionally gets inner-file renames + content rewrites (steps 4–9 below) — nested dirs have no `RALPH.md`/marker, so they need nothing beyond the dir rename.

**Foreign-config detection (Gap 6).** Also during `planMigration`, grep the project for `.ralph` references in non-tool-owned config/state files — restrict to a curated extension/name set (`*.json`, `*.jsonc`, `*.toml`, `*.yml`, `*.yaml`, and dotfiles like `.graphifyignore`, `.dockerignore`, `.prettierignore`, `.eslintignore`), excluding `node_modules`, `.git`, the migrator's own `.ralph/`/`.rauf/`/`*.bak` paths, and the already-handled `.gitignore`/`CLAUDE.md`/marker. Record hits in `foreignConfigRefs` and tell the user "these reference the old `.ralph/` path — update by hand." Do NOT rewrite them (decision #9). Keep the scope tight to config/state files so the report doesn't drown in historical log/prose matches.

**Migration sequence** (backup → mutate → commit; rollback = restore from backup):
1. **Backup**: recursive copy the **root** `.ralph/`→`.ralph.bak/`, `.ralph.json`→`.ralph.json.bak`, `CLAUDE.md`→`CLAUDE.md.ralphbak`. (Nested per-spec dirs are renamed in-place via `git mv`/`renameSync`, which is reversible without a copy; backing up only the root keeps backups bounded. CLI wrapper may skip if git tree is clean and pass `backup:false`; keep `migrate()` itself git-agnostic so core stays pure.) Record created backup paths in `backupsCreated` and **tell the user they exist + how to remove them** — these become new untracked files in the consumer's `git status`.
2. **Stale-lock cleanup**: delete every dead `.loop.lock` found by the gate across all loop dirs (the live case already refused in the gate); record in `staleLocks`.
3. **Rename loop dirs**: for each dir in `loopDirsRenamed`, `git mv`/`fs.renameSync(.ralph → .rauf)` (decision #14 — prefer `git mv` when in a git tree for blame continuity) — carries all children (backlog.json, progress.md, state.json, archive/, `.verification/`, `.loop.lock`) untouched. The **root** dir then continues through steps 4–9; **nested dirs stop here** (rename only).
4. Rename inner tool files: `.rauf/RALPH.md`→`.rauf/RAUF.md`, `.rauf/ralph.log`→`.rauf/rauf.log`. (REVIEW.md keeps its name — contents only. `archive/*-ralph.log` and `archive/*-DONE` keep their names per decision #8.)
5. `fs.renameSync(.ralph.json → .rauf.json)`.
6. **Content rewrites** via one ordered, **case-aware** `rewriteRalphStrings(text)` helper. Implement as a single regex alternation (one pass, no double-rewrite) with longest tokens first and explicit per-case mappings: `RALPH_DONE/BLOCKED/NEEDS_HUMAN/REVIEW`→`RAUF_*`, `RALPH_ROOT`→`RAUF_ROOT`, `X-Ralph-Request`→`X-Rauf-Request`, `RalphError`→`RaufError`, sentinels, `.ralph.json`→`.rauf.json`, `.ralph/`→`.rauf/`, `RALPH.md`→`RAUF.md`, then bare `RALPH`→`RAUF` / `Ralph`→`Rauf` / `ralph`→`rauf` / `$id`/title last. Rewrites the sentinels too. Missing file/sentinels → warn + skip. **Additionally scan the whole file for `ralph` tokens outside the managed block and report them in `claudeMdOutOfBlockRefs`** so the user can fix dangling references to the now-`.rauf/` paths (the migrator deliberately won't touch user prose).

9. **Marker rewrite** (single `atomicWrite` of `.rauf.json`): `delete obj.ralph; obj.rauf=true`; rename `artifactHashes["RALPH.md"]`→`["RAUF.md"]` and **recompute** hash from post-rewrite `RAUF.md`; tolerate/preserve stale extra hash keys (e.g. removed `ralph.sh`); `installedBy` `ralph-manager@`→`rauf-manager@`. Preserve `version`, `variant`, `profile`, `options`, `installedAt`. Note: recomputing the hash **blesses the current `RAUF.md` as canonical**, resetting any prior template-drift detection — acceptable/desirable.

**Preserve untouched (contents):** `backlog.json` (+`.bak`), `progress.md`, `state.json`, `archive/**`, `.verification/**`, `DONE`, any `backlog-*.json`, `notes/**`, and the **contents** of every renamed nested loop dir — item/log/verify text may legitimately contain "ralph"; rewriting it is not the migrator's job. (Note the distinction from decision #5: nested dirs are *directory-renamed* `.ralph/`→`.rauf/` so the tool can see them, but their inner files are byte-preserved — including each one's `ralph.log` filename, per decision #8's archive principle.)

**`migrateGlobal()` (`rauf migrate --global`).** Move `~/.ralph/`→`~/.rauf/` (refuse if `~/.rauf/` already exists and is non-empty → `partial`/manual). Rewrite any `config.json` contents (`rootDirectory`, `RALPH_ROOT` references) and leave `server.json`/`server.log` carried as-is (ephemeral; if a server is live, advise stopping it first since its PID/port registry is moving). Idempotent: `~/.rauf/` present + `~/.ralph/` absent → no-op.

**Backup lifecycle.** Backups (`.ralph.bak/`, `.ralph.json.bak`, `CLAUDE.md.ralphbak`) remain after a **successful** migrate. The CLI prints their paths and a one-line removal hint; an optional `--clean-backups` (or follow-up `rauf migrate --clean-backups <path>`) removes them once the user is satisfied. They are never auto-deleted on success (the user's safety net).

**Failure recovery — two modes, explicit in the CLI:**
- **Rollback** (restore from `.bak`) when a mutation step throws and leaves an inconsistent tree mid-sequence.
- **Resume-forward** (`partial` state) when re-invoked: emit only still-needed steps, each guarded by an existence/field check. Never `renameSync` onto an existing target; on collision → `partial` + warn, no overwrite.

**Dry-run / idempotency / edges:** `--dry-run` returns the full `MigrateReport` (steps + nested dirs + out-of-block refs + foreign-config refs + stale lock) with zero writes. `already_rauf`→no-op; the rewrite helper is itself idempotent. Local RALPH.md edits survive (mechanical token swap, not template re-render).
