## How the docs build actually works (read before touching it)

- **Single-source model.** `docs/*.md` are the canonical specs. The site
  (`packages/docs/`, Astro Starlight) republishes them as **symlinks** under
  `packages/docs/src/content/docs/` (e.g. `spec-cli.md → ../../../../../docs/SPEC-CLI.md`). The
  consumer pages (Getting Started / Guides) are **authored directly** as real `.md` in
  `content/docs/` — NOT symlinks, NOT in `docs/`. Cross-link the specs; never duplicate them.
- **The `.md` symlinks are tracked in git.** The **image symlinks are NOT** —
  `packages/docs/src/content/docs/images/` is **gitignored** (`.gitignore:42`). They are
  (re)created by **`scripts/setup-docs.sh`**, which the docs **`prebuild`/`predev` runs**
  (`packages/docs/package.json` → `bun run ../../scripts/generate-diagrams.ts && bash
  ../../scripts/setup-docs.sh`). So a fresh `pnpm build` in CI regenerates the SVGs AND recreates
  the symlinks — the build is self-contained. **If you add a new diagram, register its symlink in
  `setup-docs.sh`** (next to the existing `loop-lifecycle.svg` etc.).
- **Diagrams.** `scripts/generate-diagrams.ts` emits 6 SVGs into `docs/images/` (architecture +
  the 5 Tier-1). It has a generic box/connector toolkit (`renderDiagram`, `renderConnector`,
  tone-styled boxes) + the legacy architecture renderer. Each SVG embeds `prefers-color-scheme`
  CSS so it renders in dark AND light. **Verify visually** (see recipe below) — coordinates are
  hand-placed, so new diagrams need an eyeball pass for overlaps.
- **Image embeds in pages.** From a subdir page (`guides/x.md`, `getting-started/x.md`) use
  `![alt](../images/<name>.svg)`; from root `index.mdx` use `./images/<name>.svg`. The passthrough
  image service serves SVGs as-is (so an embedded image needs no Sharp).
- **Cross-link convention (base-path-independent, all relative):** sibling in same group
  `../<slug>/`; another group `../../<group>/<slug>/`; a top-level reference `../../<slug>/`
  (e.g. `../../spec-cli/`). Skills (`author-backlog`, `review-backlog`, `review-rauf-guidance`,
  `drive-rauf-loop`) are NOT pages — reference them in prose, never as links.
- **The IA / sidebar** lives in `packages/docs/astro.config.mjs`: Getting Started · Guides ·
  Reference · Internals (collapsed; the specs) · Contributing.

## Verification recipe (what proved necessary this overhaul)

```bash
# 1. Full gate exactly as CI runs it
pnpm gate                      # build (incl. docs prebuild) + schema + version + typecheck + lint + format + test

# 2. Prove the docs build is self-contained (catches the gitignored-symlink trap)
rm -rf packages/docs/src/content/docs/images   # simulate a fresh checkout
pnpm --filter @rauf/docs build                  # prebuild must regenerate SVGs + recreate symlinks

# 3. Verify diagrams in BOTH themes (coordinates are hand-placed — eyeball for overlaps)
#    Build an HTML page that <img>s the SVGs, screenshot with google-chrome headless:
/usr/bin/google-chrome --headless --disable-gpu --no-sandbox --window-size=1700,1400 \
  --screenshot=/tmp/dark.png  --force-dark-mode file:///tmp/svgview.html
/usr/bin/google-chrome --headless --disable-gpu --no-sandbox --window-size=1700,1400 \
  --screenshot=/tmp/light.png file:///tmp/svgview.html
#    Render a built page (sidebar/asides/links) by serving dist over http (file:// breaks /_astro):
( cd packages/docs/dist && python3 -m http.server 8099 ) &  # then chrome --screenshot http://127.0.0.1:8099/<slug>/

# 4. Editor TS errors on @rauf/* are PHANTOM (stale dist) — trust `pnpm typecheck`, not the LSP (see CLAUDE.md).
```
